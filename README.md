# Secure Cloud Storage

A Flask web app built to practice real-world cybersecurity concepts: safe password storage, multi-factor authentication, and client-managed encryption — built as part of my cybersecurity learning and internship work.

## Features

- [x] User registration and login
- [x] Password hashing with bcrypt (salted, length-safe)
- [x] Session cookies with HttpOnly and SameSite flags
- [x] Parameterized SQL queries (SQL injection protection)
- [x] Email verification (expiring token)
- [x] Forgot password with expiring reset links
- [x] OTP email MFA (6-digit code, 5-minute expiry, 5-try limit)
- [x] Authenticator app (QR/TOTP) MFA
- [x] AES-256-GCM encryption/decryption — client-managed storage (no files stored on the server; user uploads/downloads the encrypted file to their own cloud, e.g. Google Drive or OneDrive)
- [x] File type and size validation (max 10 MB, allowed extensions only)
- [x] Admin/user roles (role checked server-side on every request)
- [x] Activity logging (logins, failed attempts, MFA events, encrypt/decrypt, admin access attempts)
- [x] CSRF protection on all forms
- [x] Login rate limiting (lockout after 5 failed attempts, 15-minute cooldown)

## Security Features Explained

- **Password storage:** passwords are hashed with bcrypt (includes a random salt), never stored in plain text. A 72-byte length check prevents a known bcrypt crash from oversized input.
- **Two-factor authentication:** after a correct password, the user must also enter a one-time code — either emailed (5-minute expiry) or generated by an authenticator app (Google Authenticator, scanned via QR code).
- **Encryption, not storage:** this app does not keep any uploaded files. It encrypts a file with AES-256-GCM (which also detects tampering) and hands the encrypted file back to the user, who stores it in their own cloud. Decryption works the same way in reverse. This means even if the server were compromised, there is nothing to steal.
- **CSRF protection:** every form includes a one-time token checked by the server, so a malicious website cannot submit forms on a logged-in user's behalf.
- **Rate limiting:** login attempts are tracked by IP + email; after 5 wrong passwords, that combination is locked for 15 minutes.
- **Admin role:** checked against the database on every request (not just the session), so there is no way to escalate privileges from the browser.
- **Activity logs:** every security-relevant event (registration, login success/failure, MFA failures, encrypt/decrypt, denied admin access) is recorded with a timestamp and IP.

## Known Limitations (Honest Gaps)

- Email sending currently prints to the terminal instead of sending real email (easy to swap for Gmail SMTP).
- The TOTP secret is stored in plain text in the database; a production system would encrypt it.
- Activity logs are stored in the same database; a production system would send them to a separate, tamper-resistant log store.
